# Internationalized messages

The API is i18n-ready without an additional runtime package. Message catalogs live in `src/i18n/messages.ts`.

`Accept-Language` selects `es` or falls back to `en`:

```bash
curl -H 'Accept-Language: es' \
  -H 'Content-Type: application/json' \
  -d '{"token":"","password":"short"}' \
  http://localhost:3000/api/v1/auth/password-reset/confirm
```

Example catalog usage:

```ts
import { resolveLocale, translate } from '@/i18n/messages';

const locale = resolveLocale(request.headers['accept-language']);
const message = translate(locale, 'auth.reset.invalid');
```

Message keys remain stable even when translations change. JSON field names and machine-readable error codes are never translated. Add a locale and matching `Record<MessageKey, string>` entry in the catalog, then document the supported locale in the API description.
